# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

.NET developers maintaining packages and toolchains in an agent conversation.

## Product Purpose

dotnet-nudge reports maintenance evidence and helps developers plan explicitly
approved changes. Native questions are the primary interaction.

## Operating Context

The shared plugin supports multiple agent hosts. Copilot hosts with a
bidirectional canvas can additionally offer a shared maintenance dashboard.
NuGet supports package selection; SDKs and workloads share its overview.

## Capabilities and Constraints

Package selection includes current/target versions, project and framework
scopes, vulnerability evidence, publisher information and deferred items.
“Update selected” requests an exact plan from the agent, not immediate edits.
Metadata acquisition, downloads, edits and trials retain their approval boundaries.
Missing evidence must remain visible rather than appearing up to date.

## Brand Commitments

Use .NET purple (#512bd4) for primary/selection accents and the official mark
where appropriate, with Copilot-native surfaces, controls, typography and
accessibility. The canvas title is dotNudge. Do not repeat the host's icon,
title or workspace heading inside the content; Refresh shares the tabs row.

## Product Principles

Show package choice, version change and critical status first. Reveal secondary
controls, provenance and technical detail deliberately rather than presenting
all available information by default. Concision must not hide missing coverage,
broaden a selection, or weaken approval boundaries.
